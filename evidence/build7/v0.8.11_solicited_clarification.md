# v0.8.11 Solicited Clarification Continuity

Runtime defect reproduced from v0.8.10: after `VoiceStrike, I think I've got the wrong part.`, VoiceStrike asked for the component; a natural direct reply `B184` could arrive after the normal 15 s wake window and was rejected as `WAKE_REQUIRED`, leaving the command COLLECTING and read tools blocked.

Fix: on non-interrupted `reply.done`, if the current command is COLLECTING, AmbientSpeechGate opens a one-shot 30 s clarification window bound to that exact commandId. A clarification-like reply can be accepted without repeating the wake phrase, receives conversational authority for read-tool continuity, consumes the window, and starts a fresh ordinary wake window. Unrelated ambient speech does not consume the window. Wrong-command and expired windows do not transfer authority. Critical reverse/confirm-reverse speech is unchanged: CriticalSpeechTrustGate runs first and still requires an explicit VoiceStrike wake phrase.

Grounding: a read tool blocked before endpoint execution now explicitly tells the agent not to claim tool failure/unavailability and not to ask the worker for system-known job/station identifiers.
