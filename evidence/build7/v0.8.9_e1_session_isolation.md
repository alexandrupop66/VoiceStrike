# VoiceStrike BUILD 7 v0.8.9 — E1 session isolation fix

## Runtime defect reproduced from v0.8.8

A long-lived Worker voice session completed E3 recovery, then the demo state was reset from the Supervisor view without reconnecting the Worker voice session. The next worker request was:

- `VoiceStrike, I think I've got the wrong part.`
- `B184.`

The read tools were blocked as `NEEDS_CLARIFICATION / command still incomplete`.

## Root cause

`CommandRegistry.shouldMergeClarification()` allowed any READY command that already had a component to absorb any later operational intent. A completed `REVERSE_SCAN` command therefore absorbed the new `WRONG_COMPONENT` utterance. Because `detectOperationalIntent()` resolves the earlier reverse language first, the accumulated command remained `REVERSE_SCAN`. The following `B184` then started a separate component-only command, which correctly remained `COLLECTING`; `get_current_job` and `check_component` were consequently blocked.

This was command-lifecycle contamination, not a failure of `get_current_job`, `check_component`, SQLite, or the truthful tool-reporting layer.

## Fix

READY-command merging is now allow-listed only for the recovery progression that intentionally preserves one commandId:

- `SCAN_CONTEXT -> MISTAKEN_SCAN`
- `SCAN_CONTEXT -> REVERSE_SCAN`
- `MISTAKEN_SCAN -> REVERSE_SCAN`
- `REVERSE_SCAN -> REVERSE_SCAN` (separate protected confirmation turn)

A new unrelated intent such as `WRONG_COMPONENT` starts a fresh command. The read-tool readiness gate remains unchanged; it is not weakened.

## Safety effect

- No mutation gate was relaxed.
- No read tool is allowed on an incomplete command merely to mask the bug.
- Existing stale-command and immutable TurnAuthority protections remain unchanged.
- Recovery commandId continuity remains unchanged.

## Added deterministic regression

The reliability suite now executes:

`MISTAKEN_SCAN -> REVERSE_SCAN -> REVERSE_SCAN(confirm) -> WRONG_COMPONENT -> B184`

and asserts:

1. recovery stays on one commandId;
2. the subsequent wrong-component report gets a new commandId;
3. B184 stays on that new command;
4. the new command becomes `READY` with `WRONG_COMPONENT`;
5. stale `reverse scan` text is absent from the fresh command context.
