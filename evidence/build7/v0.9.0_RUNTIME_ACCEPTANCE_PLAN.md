# BUILD 7 v0.9.0 — Runtime Acceptance Plan

**BUILD 7 IMPLEMENTATION: FINAL CANDIDATE — BUILD 7 RUNTIME ACCEPTANCE: PENDING.**

Nothing in this document has been executed. Every item below requires a real Windows machine, a
real microphone, real speakers and a real television/background source. No result here may be
filled in from automated evidence.

## Setup

1. `npm install`, `.env` with `ASSEMBLYAI_API_KEY`, `npm run build`, `npm start` (or the existing
   launcher script). No PowerShell ExecutionPolicy bypass and no hidden launch behaviour.
2. Open the Worker view, press **Start VoiceStrike**, allow the microphone.
3. Open the DEV panel (100 signals). Before each test press **Reset demo state** in Supervisor,
   then **Copy diagnostics JSON** after the test and attach the export to the result.
4. Record for every run: `sessionId`, `epoch`, `commandId`, mutation count, and the supervisor
   state of `ACT-SCAN-B184` and `JOB-482`.

## R20 — E1 deterministic sequencing (defect 5.1)

1. `VoiceStrike, I think I've got the wrong part.` → agent asks for the component.
2. `B184.`

**Expected.** One `commandId` throughout. Telemetry order:
`check_component` → `MISMATCH` → `report_exception` → `mutation_started` → `mutation_completed`
→ `verification_started` → `verification_passed` → `verified_success` → `update_job_status`
→ `verified_success` → `check_inventory(B148)`.
Supervisor: `JOB-482 = BLOCKED`, one open `WRONG_COMPONENT` exception.
The spoken answer names the required component, states the job is blocked and the mismatch
logged, and gives the location of B148 — and only after both verifications.

**R20-B negative control.** If the model requests the block early, telemetry must show
`workflow_precondition_required` with `tool_call_attempted=false`, and the later legitimate
block must still succeed exactly once. VoiceStrike must never say the job is blocked before
`verified_success` for `update_job_status`.

## R21 — Truthful grounding (defect 5.2)

Trigger a locally blocked read (speak an incomplete command, then let the agent attempt a tool).

**Expected.** Telemetry `tool_blocked_local`, `tool_call_attempted=false`. The spoken reply asks
for the missing worker-provided information. It must **not** contain "I cannot retrieve",
"the tool failed", "the system is unavailable", or any claim that state changed.

## R22 — Read-only bootstrap (defect 5.3)

1. `VoiceStrike, where can I find B148?`
2. If asked whether it is for the current job: `VoiceStrike, for my current job.`

**Expected.** `get_current_job` and `check_inventory` are actually attempted
(`tool_attempted`, `attempted=true`). VoiceStrike answers with the authoritative location and
quantity. It must **not** ask the worker for a job or station ID.

## R23 — Idle ambient / autonomous reply (defect 5.4)

Fresh reset, fresh voice session, television at normal room volume, **human silent for 3 minutes**.

**Expected.** Zero audible VoiceStrike output. Telemetry shows `ambient_turn_rejected` and, if
the provider generated anything, `orphan_reply_suppressed`. No `tool_requested`, no
`action_authorised`, no worker turn in the transcript, no self-reply cascade.

**R23-B.** Repeat the same TV exposure *while a command-bound clarification window is open*
(after the agent asks "What component are you observing?"). The window must survive, and the
worker's `B184` 10–15 s later must still be accepted on the same `commandId`.

## R24 — Natural cancellation (defect 5.5)

1. `VoiceStrike, I scanned B184 by mistake.` → inspection.
2. `VoiceStrike, reverse scan B184.` → prepared, not executed.
3. `VoiceStrike, actually don't reverse it.`

**Expected.** `protected_action_cancelled` in telemetry; the spoken reply confirms the reversal
was cancelled and nothing changed; VoiceStrike does **not** keep standing by for the
confirmation phrase. Mutation count 0, `ACT-SCAN-B184 = ACTIVE`.
Then say `VoiceStrike, confirm reverse scan B184.` — it must be refused as
`CONFIRMATION_CANCELLED`, mutation count still 0.
Repeat with `VoiceStrike, cancel that.` and `VoiceStrike, stop.`
Negative control: with **no** pending action, `VoiceStrike, don't block the job, just tell me
where B148 is.` must be handled as a normal request, not as a cancellation.

## R25 — Confirmation expiry (defect 5.6)

1. Prepare a reversal, then wait past the 20 s confirmation TTL without confirming.
2. `VoiceStrike, confirm reverse scan B184.` → must report expiry, mutation 0.
3. `VoiceStrike, reverse scan B184.`

**Expected.** `protected_action_expired` and `command_invalidated` in telemetry. Step 3 obtains
a **new** `commandId`, requires a fresh `inspect_last_action`, and the `command_ready` string
must contain only the new phrase — never a concatenation such as
`"Voice strike, confirm reverse scan B184. Voice strike, reverse scan B184."`

## R26 — Full demo reset (defect 5.7)

1. Create pending state (prepare a reversal, leave a COLLECTING command).
2. Switch Worker → Supervisor → Worker. **Session must survive**: same `sessionId`, transcript
   preserved, no `connection_lost`, no new "Start VoiceStrike" prompt (R18 regression).
3. Press **Reset demo state**.

**Expected.** Backend reseeded; `session_epoch_changed` in telemetry; worker transcript, tool
list and DEV panel cleared; the voice session is **not** disconnected. A pre-reset confirmation
phrase spoken afterwards cannot mutate. No pre-reset async event repopulates the new run.

## R27 — Telemetry and diagnostics (defect 5.8)

**Expected.** No `tool_called` event anywhere. Intent, authorisation, local refusal and real
execution are distinguishable. The DEV panel retains ≥50 (configured 100) events through a noisy
run. **Copy diagnostics JSON** produces valid JSON correlating `sessionId`, `epoch`, `turnId`,
`commandId`, `actionId`, `componentId`, `authorityId`, `intent`, `tool`, `attempted`,
`resultClass`, `latencyMs`, `timestamp` — and contains no API key or secret.

## R28 — 30-utterance controlled audio corpus (spec §9)

Run `tests/reliability/reliability-corpus.json` (41 cases) as spoken audio, twice: once with
keyterms on, once with `?keyterms=off`, using the **same speaker and the same utterances**.

Categories present and to be exercised: `baseline`, `technical_id`, `fragmented`, `correction`,
`interruption`, `sanity`, `ambiguity`, `ambient`, `wake_control`, `protected_confirmation`,
`cancellation`, `accent`, `noise`.

Record per case: transcript received, entity resolved or clarified, mutation count, outcome.
Then compute Unsafe Action Rate, False Success Rate, Critical Entity Safe Resolution, correction
handling, and the keyterms A/B difference.

**Do not fabricate any of these numbers.** If a case was not run, record it as not run.

## R29 — Regression of E1 / E2 / E3 over live audio

- **E1** wrong component: R20.
- **E2** missing inventory: `VoiceStrike, the location for B148 is empty.` → `check_inventory`
  → explicit EMPTY report → `report_inventory_discrepancy` (verified) →
  `find_alternative_inventory`. Existing demo data only; no ERP, no external warehouse.
- **E3** mistaken scan: Inspect → Prepare → separate-turn Confirm → exactly one Reverse →
  independent Inspect → `VERIFIED_SUCCESS`, `ACT-SCAN-B184 = REVERSED`, `RECOVERY VERIFIED`.

## Known limitation (unchanged)

Without speaker identification, a nearby person who deliberately says the wake phrase and a
complete valid protected command can still be indistinguishable from the worker at the STT
layer. v0.9.0 does not change this and does not claim to.
