# VoiceStrike BUILD 7 v0.9.5 — E2 Command Continuity + Evidence Root Cause

## Runtime evidence

A long Windows session exposed a failure that the isolated v0.9.4 E2 tests did not reproduce. The typed E2 resolver was already correct: `B148 isn't at C12. The location is empty.` resolved `component_id=B148`, `location_id=C12`, and explicit EMPTY. The failure was command lifecycle churn.

Observed order:

1. `check_inventory` completed under an existing command.
2. A bare `VoiceStrike.` was accepted as a brand-new operational command.
3. The explicit E2 report then became yet another commandId.
4. A delayed `check_inventory` tool request remained bound to the prior reply command and was correctly refused as `COMMAND_MISMATCH` before any endpoint call.
5. Redundant model clarification (`yes`, restated EMPTY) kept creating additional commands, so the model entered a safe but unusable clarification loop.

Safety held: stale/mismatched tool calls were refused locally and no unsafe mutation occurred. The problem was continuity and usability, not weak authorisation.

## Structural fix

### Wake-only control

A transcript that is only `VoiceStrike` is now a wake/control event. It:

- opens the normal wake window;
- is shown in the transcript;
- does not call `CommandRegistry.acceptFinalTranscript`;
- does not create/invalidate an operational command;
- does not mint new tool or mutation authority.

### E2 command continuity

Once the active command intent is `MISSING_INVENTORY`, E2-related clarification remains on the same commandId for the 60-second clarification-retention period, including explicit wake-qualified short responses if the model redundantly asks a yes/no question. A clearly different intent still starts a new command.

The mutation evidence remains the accumulated typed command context containing explicit EMPTY + resolved component/location. A short response by itself is not sufficient mutation evidence.

### E2 model policy

When the accepted command already contains component + location + explicit EMPTY, the agent is instructed not to ask `Did you check that location?` or request a redundant yes/no confirmation. It should refresh `check_inventory` itself if the authoritative stock precondition is missing/stale, then perform the deterministic discrepancy workflow.

### Evidence retention

The worker transcript was previously capped at 24 entries, causing the first part of long stress tests to disappear. v0.9.5 changes:

- transcript history: 500 entries;
- tool history: 100 entries;
- reliability history: 200 entries;
- `Copy transcript` control;
- `Export transcript JSON` control.

Explicit Demo Reset / new connection still clears session evidence intentionally.

## Safety invariants unchanged

- False transcript may happen. False mutation must not.
- Stale command tool calls remain blocked; authority is never transferred to another command.
- `report_inventory_discrepancy` still requires typed B148/C12/EMPTY evidence, a recent authoritative matching stock check, and post-mutation verification.
- E1 sequencing and E3 protected recovery were not weakened.
