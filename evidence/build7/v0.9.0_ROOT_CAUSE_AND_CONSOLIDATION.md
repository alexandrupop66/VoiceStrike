# BUILD 7 v0.9.0 — Root Cause and Consolidation

Status: **BUILD 7 IMPLEMENTATION: FINAL CANDIDATE — RUNTIME ACCEPTANCE: PENDING**

Starting codebase: `VoiceStrike BUILD 7 Reliability v0.8.11 CLEAN`.
This document maps every runtime-confirmed defect to its root cause, the structural mechanism
that resolves it, the automated regression that holds it, and what still requires real audio.

---

## 1. Cross-cutting root cause

The eight confirmed defects are not eight independent bugs. They are symptoms of two
architectural properties of v0.8.11.

### 1.1 No single owner of the conversation lifecycle

Session state lived in independent mutable holders that did not invalidate each other:

| Holder | Owned | Invalidated by |
|---|---|---|
| `CommandRegistry.active` | command identity, readiness | correction, cancellation phrase, new intent |
| `CriticalConfirmationGate.prepared` | prepared reversal | **only its own 20 s TTL** |
| `recoverySpeechContext` | inspection authority | tool result, 120 s TTL |
| `suppressAmbientReply` | reply suppression | **any** `reply.done`, including another reply's |
| `ambientGate` windows | wake / clarification | own timers |
| `TurnAuthorityRegistry` | mutation authority | command invalidation, reconnect, TTL, consumption |

Every gap between two holders became a defect:

- the prepared action survived its command being corrected → **5.5** cancellation failed;
- the prepared action's expiry never closed the command → **5.6** expired transcript leaked into
  a fresh command (`"confirm reverse scan B184. ... reverse scan B184."`);
- a boolean shared by all replies was cleared by an unrelated reply boundary → **5.4** idle
  TV speech produced autonomous spoken replies and a self-reply cascade;
- nothing browser-side was reset by "Reset demo state" → **5.7** conversational contamination
  across supposedly isolated runtime tests.

### 1.2 Authority to *act* and authority to *claim* were not derived from evidence

- Mutation ordering for E1 existed only in the agent prompt. A premature
  `update_job_status(BLOCKED)` therefore became a real HTTP mutation attempt, travelled through
  the Safe Action Executor, **consumed the single per-turn attempt of that tool**, and the later
  legitimate block was then refused as `AUTHORITY_ALREADY_CONSUMED` — **5.1**.
- "Did a tool fail?" and "did state change?" were answered from whichever local variable was in
  scope. A read blocked by a local gate (`tool_call_attempted=false`) was verbalised as
  *"I cannot retrieve your current job information"*, and an E1 answer claimed *"the job is now
  blocked"* in a run where the blocking mutation never verified — **5.2**.
- Readiness was one gate for all tools, so `get_current_job` — whose whole purpose is obtaining
  system context — was blocked while the command was still COLLECTING, forcing the agent to ask
  the worker for identifiers the system already knows — **5.3**.
- Telemetry named intent and execution with the same event (`tool_called` with
  `tool_call_attempted=false` in its own detail) — **5.8**.

### 1.3 The consolidation

v0.9.0 introduces explicit lifecycle ownership and evidence-derived authority:

```
SessionEpoch
  └── AcceptedTurn ── TurnAuthority (immutable, v0.8.8)
        ├── Command ── WorkflowPhase ─────────────┐
        ├── PendingProtectedAction (PREPARED →    │  deterministic
        │      CONSUMED | CANCELLED | EXPIRED)    │  precondition
        ├── ReplyBinding (authorised | orphan)    │
        └── ClaimEvidence ── ClaimGrounding ──────┘
```

`INPUT → ACCEPT/REJECT → COMMAND → WORKFLOW PHASE → AUTHORISE → ACT → VERIFY → RESPOND`.
Every later event is causally attributable to the accepted earlier state that authorised it;
rejected, expired, cancelled and stale state is invalidated at a boundary rather than left to
be discovered by the next attempt.

No abstraction was added for elegance. Each of the six new modules removes a runtime-confirmed
class of stale-state or race defect, and the number of independently mutable session holders is
lower after the change, not higher.

## 2. Defect → root cause → structural fix → regression

### 5.1 E1 mutation sequencing was non-deterministic

- **Root cause.** Ordering lived in the prompt. A premature mutation was an *attempted* HTTP
  call, so `turnAuthorities.consumeMutation()` fired inside `request()` before the server could
  refuse it; the legitimate later step then hit `MUTATION_ALREADY_CONSUMED`.
- **Invariant enforced.** The LLM must not be the authority deciding whether mutation step 2
  may precede mutation step 1.
- **Mechanism.** `client/src/reliability/workflow.ts` — `WorkflowPolicy`, consulted in
  `handleToolCall` **before** any endpoint call and **before** any authority is consumed.
  Facts are written only from authoritative evidence: a `MISMATCH` verdict from
  `check_component`, a positive `check_inventory`, and mutations that reached
  `VERIFIED_SUCCESS` through independent verification. An out-of-order request returns
  `PRECONDITION_REQUIRED` with the missing prerequisite named; `tool_call_attempted=false`;
  nothing is consumed; the legitimate step remains available exactly once.
- **Telemetry.** `reliability.workflow_precondition_required`, `reliability.workflow_phase`.
- **Regressions.** R-A, R-B.

### 5.2 Operational success/failure grounding was incomplete

- **Root cause.** No single derivation of what the evidence permitted the agent to say.
- **Mechanism.** `client/src/reliability/claims.ts` — an append-only `ClaimEvidence` stage list
  (`TOOL_REQUESTED`, `TOOL_AUTHORISATION_CHECKED`, `TOOL_BLOCKED_LOCAL`, `TOOL_ATTEMPTED`,
  `TOOL_RETURNED_FAILURE`, `MUTATION_STARTED`, `MUTATION_COMPLETED`, `VERIFICATION_STARTED`,
  `VERIFICATION_FAILED`, `VERIFICATION_PASSED`, `VERIFIED_SUCCESS`) and one function,
  `groundClaims()`, that derives permissions from it. The rules are asymmetric on purpose: a
  claim is permitted by positive evidence only.
  - `may_claim_tool_failure = TOOL_ATTEMPTED && TOOL_RETURNED_FAILURE`
  - `may_claim_state_changed = VERIFIED_SUCCESS && VERIFICATION_PASSED`
  The derived `claim_grounding` object — including an explicit `forbidden_claims` list — is
  attached to **every** tool result the model receives, so permission travels with evidence.
- **Regressions.** R-C, R-D, CG-1…CG-5.

### 5.3 Read-only context tools were over-gated

- **Root cause.** One readiness gate (`isReady(commandId)`) for read and mutation alike.
- **Mechanism.** `client/src/reliability/toolPolicy.ts` classifies every tool centrally:
  `CONTEXT_READ` (`get_current_job`) may bootstrap any accepted turn; `ENTITY_READ`
  (`check_component`, `check_inventory`, `find_alternative_inventory`) requires a safely
  resolved component but not mutation readiness; `AUTHORITATIVE_READ` (`inspect_last_action`)
  still requires a READY command, preserving the v0.8.1/v0.8.6 invariant that incomplete speech
  cannot pull the last scanned component out of authoritative state and present it as
  worker-supplied; `MUTATION` keeps every existing gate.
  An unconfirmed reconstructed ID still blocks entity reads; an ambiguous or unresolved
  component still causes clarification and is never guessed; read bootstrap grants no mutation
  authority, and every class still requires an accepted, wake-authorised turn authority.
- **Regressions.** R-E, R-P, TP-1…TP-5.

### 5.4 Idle TV/ambient speech caused autonomous replies

- **Root cause.** `suppressAmbientReply` was one mutable session boolean cleared at the next
  `reply.done`, whichever reply that was. A reply generated for an already-rejected transcript
  could therefore be spoken.
- **Mechanism.** `client/src/reliability/replyAuthority.ts` binds each reply, once and
  immutably, to the accepted turn that caused it. Only an ACCEPTED turn opens a turn; rejected
  transcripts can neither open nor close one. A reply beginning with no open accepted turn is an
  **orphan**: audio is not played, the agent transcript is not shown as an authoritative turn,
  and `noteAgentText` is not fed (so a suppressed reply cannot poison echo detection). The open
  turn is held across outstanding tool work, so a television utterance arriving between a tool
  call and its result reply cannot silence the worker's real answer. One greeting per epoch is
  authorised because the provider speaks it before any worker turn exists.
  The command-bound clarification window that already worked is preserved, and additionally
  hardened: it now accepts only a real operational continuation, so a televised "yes" can no
  longer take or transfer it.
  This uses only locally observable provider events. **No provider capability was invented**;
  AssemblyAI exposes no per-turn confidence and none is fabricated.
- **Telemetry.** `reliability.reply_requested`, `reliability.reply_bound_to_turn`,
  `reliability.orphan_reply_suppressed`, `reliability.ambient_turn_rejected`.
- **Regressions.** R-F, R-G, R-Q.

### 5.5 Natural cancellation did not invalidate a pending protected action

- **Root cause.** `"VoiceStrike, actually don't reverse it."` contains *actually*, so
  `CommandRegistry` took the **correction** branch and built a replacement command carrying the
  reversal context forward. `CriticalConfirmationGate.prepared` was never touched; only its TTL
  could clear it.
- **Mechanism.** `client/src/reliability/cancellation.ts` detects cancellation conservatively
  and contextually — only when a compatible protected action is pending, never when the phrase
  names a different component, never when the phrase is a confirmation. It is evaluated on an
  accepted turn **before** ordinary command semantics, so the correction path can no longer
  carry the abandoned action forward. On cancellation the prepared authority is destroyed
  immediately (`CriticalConfirmationGate.cancel()` writes a `CANCELLED` tombstone), the owning
  command is invalidated, the recovery inspection context for that command is dropped, and the
  cancellation turn becomes a terminal `CANCELLED` command carrying no operational intent.
  Mutation count remains 0; a later replay of the old confirmation is refused as
  `CONFIRMATION_CANCELLED`; safety does not depend on the TTL.
  Existing wake/trust requirements for protected commands were **not** weakened.
- **Regressions.** R-H, R-H2.

### 5.6 Confirmation expiry did not terminate the old command

- **Root cause.** Expiry was discovered lazily inside `assessReverse`. The command stayed
  active, and `shouldMergeClarification` kept merging `REVERSE_SCAN → REVERSE_SCAN`, so the
  expired confirmation text concatenated into the new command context.
- **Mechanism.** Cancellation and expiry now share one invalidation mechanism.
  `CriticalConfirmationGate.sweep()` runs on every user transcript and every reply boundary;
  expiry writes an `EXPIRED` tombstone, and `voiceAgent.sweepProtectedAction()` invalidates the
  owning command, drops its recovery inspection authority and clears its clarification window.
  A fresh `reverse scan B184` therefore obtains a new `commandId`, must inspect again before the
  trust gate will accept the protected phrase, and cannot absorb the expired transcript. A stale
  confirmation can never mutate.
- **Regressions.** R-I.

### 5.7 Demo reset did not reset the demo session

- **Root cause.** The reset was a backend reseed only.
- **Mechanism.** `client/src/reliability/session.ts` introduces `SessionEpoch`.
  `VoiceAgentClient.resetSession('DEMO_RESET')` bumps the epoch and clears, in one place, the
  command registry, turn authorities, prepared confirmation and tombstone, ambient/clarification
  windows, duplex guard, workflow facts, reply bindings, recovery context, in-flight mutation
  bookkeeping, pending tool results and transcript state. Pending tool results are stamped with
  their epoch and dropped if the epoch has moved, so a pre-reset asynchronous event cannot
  repopulate the new session. `SupervisorView` dispatches the reset event; `VoicePanel` performs
  it and clears its own display.
  The live voice session is **not** disconnected: Worker ↔ Supervisor switching remains pure
  presentation and the v0.8.10 persistence behaviour is unchanged.
- **Regressions.** R-J, R-K.

### 5.8 Telemetry was ambiguous and too short

- **Root cause.** `reliability.tool_called` was emitted for intent, including when
  `tool_call_attempted=false`; the DEV panel kept 12 events.
- **Mechanism.** The ambiguous event is gone. The lifecycle is now
  `tool_requested → tool_authorisation_checked → (tool_blocked_local | tool_attempted) →
  tool_result`, plus `mutation_started/completed`, `verification_started/passed/failed` and
  `verified_success`. Every event carries correlation identifiers: `sessionId`, `epoch`,
  `turnId`, `commandId`, `actionId`, `componentId`, `authorityId`, `intent`, `tool`,
  `attempted`, `resultClass`, `latencyMs`, `timestamp`.
  The DEV panel keeps 100 signals and offers **Copy diagnostics JSON** — correlation identifiers
  only; no API keys, tokens or raw audio are ever exported.
  `GET /api/reliability/metrics` derives counters from recorded telemetry only.
- **Regressions.** Structural checks on the event vocabulary and identifier set.

## 5. Superseded assertions

Six structural assertions encoded v0.8.11 implementation details that this build deliberately
replaces. None was weakened; each was replaced by a stricter or more specific assertion:

| Old assertion | Why superseded | Replacement |
|---|---|---|
| `turnAuthorities.reset()` appears exactly 3× | authority clearing is no longer duplicated per call site | asserted on the single epoch owner + ≥4 lifecycle boundaries |
| Read tools require command readiness | defect 5.3 | read readiness decided per tool class; mutations still require READY; authoritative inspection still requires READY |
| Ambient replies suppressed via `suppressAmbientReply` | defect 5.4 | flag must be **absent**; per-reply immutable binding asserted instead |
| One hand-written truthful-reporting sentence | defect 5.2 | derived claim grounding asserted, including the attempted/verified rules |
| Rejected critical speech sets the suppression flag | defect 5.4 | rejected critical speech must produce a dead conversational turn |
| Latency stages include `reliability.tool_called` | defect 5.8 | the ambiguous event must be absent; the six-event lifecycle asserted |
