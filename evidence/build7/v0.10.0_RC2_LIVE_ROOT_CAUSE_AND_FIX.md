# VoiceStrike v0.10.0 RC2 — Live Root Cause and Closure Fix

Date: 20/09/2026
Status: automated closure candidate; Windows + AssemblyAI live acceptance still required.

## Evidence that triggered RC2

The first v0.10.0 Windows session showed four runtime defects despite the command-context refactor:

1. The first `get_current_job` after the connection greeting could be rejected with `COMMAND_MISMATCH`.
2. E1 kept the clarification `B184.` on the correct command, but the server rejected the later mutation because it still required an operational keyword in accumulated transcript text.
3. A complete E2 utterance (`B148 isn't at C12. The location is empty.`) could still enter a redundant confirmation/tool-order loop before discrepancy evidence existed on the same command.
4. The model spoke D05/4 although no completed `find_alternative_inventory` tool result existed.

## Corrected root cause

The remaining failures shared two authority leaks:

- provider reply ownership could survive across a fresh speech onset long enough for a delayed old reply/tool to compete with a new accepted turn;
- typed CommandContext was authoritative at the client, but the mutation guard and final spoken response still allowed transcript/model semantics to participate in operational authority.

## Structural correction

### Reply ownership boundary

Fresh worker speech interrupts the current reply binding. An old command may survive only as a short stale delayed-tool owner so a late old tool is rejected against its original command; it can never inherit the newly accepted command.

### Typed mutation authority

Mutation requests now carry `X-VoiceStrike-Workflow` and `X-VoiceStrike-Command-Ready`. The server requires those values and keeps transcript checks as basic sanity only (`requireOperationalSignal: false`). Endpoint-specific same-command prerequisites still provide the actual business/safety authority.

### Deterministic E2 continuation

Once E2 owns typed `component + location + observedEmpty=true` and the authoritative inventory read confirms positive stock at that exact primary location, code owns the remaining sequence:

`check_inventory -> report_inventory_discrepancy -> independent verify -> find_alternative_inventory`

Provider/model tool ordering is no longer allowed to decide whether the discrepancy or alternative lookup occurs.

### Hard spoken-claim gate

E1/E2/E3 reply PCM is buffered until the final agent transcript is checked against command-scoped authoritative evidence. Unsupported mutation, location, or quantity claims are dropped before audio playback. In particular, D05/4 cannot be spoken unless exact alternative-inventory evidence exists.

## Safety preserved

- immutable TurnAuthority and single mutation consumption
- protected E3 PREPARE / CONFIRM
- cancellation and stale confirmation blocking
- no blind mutation retry
- independent post-mutation verification
- ambient/wake and orphan-reply suppression
- command-scoped evidence prerequisites on server

No existing safety gate was weakened to make conversational continuity work.
