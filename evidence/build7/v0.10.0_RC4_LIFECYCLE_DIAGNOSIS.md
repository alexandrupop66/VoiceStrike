# VoiceStrike v0.10.0 RC4 — Lifecycle root cause and structural fix

Date: 21/09/2026. Scope: live runtime orchestration only. Business logic, CommandContext, TurnAuthority,
protected confirmation, verification and server gates are unchanged.

## Proof

`scripts/test-event-pipeline-rc4.mts` drives the real `VoiceAgentClient` event handler against the real
Express API and an isolated SQLite file, simulating only the provider WebSocket and speakers.

- On unmodified RC3 it reproduces the live symptoms end to end (`v0.10.0_RC4_harness_against_RC3_baseline.txt`):
  `PROTECTED_PROMPT_NOT_FINISHED` → `reverse_last_scan` `CRITICAL_SPEECH_NOT_TRUSTED` → `COMMAND_MISMATCH` →
  repeated `inspect_last_action`, continuation `NO_ACCEPTED_TURN`, completed result stranded after a TV delta.
  (Checks P2-owner, P4-dwell and P6 also rely on RC4-only telemetry fields, so their RC3 failures are partly
  instrumentation; P1, P3, P8 are purely behavioural.)
- On RC4: 27/27.

## Root causes (RC3)

| ID | Defect | Location |
|---|---|---|
| C1 | Speech onset (also TV) nulled the reply binding; `reply.done` then returned null, so the protected window never opened and the open turn leaked. The provider's answer to a locally rejected transcript was bound audibly to the leaked turn; its `reverse_last_scan` resolved to the inspect turn → `CRITICAL_SPEECH_NOT_TRUSTED`, or with no owner → `COMMAND_MISMATCH`. | `ReplyAuthorityRegistry.interruptCurrentReply/finishReply/beginReply`; `voiceAgent` `reply.done` |
| C2 | Tool work was registered only after all awaits; a turn with an in-flight tool closed at `reply.done` and its continuation was orphaned. | `handleToolCall` (`markPendingWork` position) |
| C3 | 5 s stale tail owned any tool and `noteToolRequest` rehydrated the old command over a newer accepted turn. | `commandIdForToolRequest`, `noteToolRequest` |
| C4 | `tool.result` handoff gated on a global last-event scalar written by every event (TV deltas included). | `flushPendingToolsIfIdle` / `lastEventType` |
| C5 | Unserialized async dispatch (`void handleMessage`) let `tool.call` run during `await` inside `transcript.user`, before the verdict/authority grant. | `ws message` listener |
| R | RC3 set all tools to `execution_mode: 'hold'`; AssemblyAI documents `interactive` for sub-5 s lookups and states that under `hold` user speech does not trigger replies while a tool is in flight. | TOOLS |

## RC4 fix (one coherent change)

1. **Ordered pipeline.** Provider events go through one queue; receipt time is stamped before queuing and
   used as speech-onset evidence. Tool I/O runs off the queue; completion re-enters as `commitToolResult`.
2. **Reply-causality ledger** (`replyAuthority.ts`): every final transcript is a fence; an accepted turn owns
   one initial reply plus one continuation per handed-off result; any other reply is orphan. Onset is recorded,
   never revoking. Calls are registered by `call_id` at admission and hold their turn. No stale tail, no
   rehydration over a newer turn; ambiguity → no owner → refused before any endpoint. Protected turns attribute
   only their expected tool outside a reply. Wake-only utterances are fences.
3. **Documented handoff rule**: send `tool.result` only when `reply.done` is the latest of
   `reply.started` / `input.speech.started` / `reply.done`. Interrupted-reply results (queued or still in flight)
   are dropped and recorded; they release their turn hold.
4. **Execution mode** reverted to documented `interactive`.
5. **Instrumentation**: `reliability.provider_event` (seq, receipt time, status/call_id/ids, ledger snapshot,
   handoff state), `tool_result_sent` (handoff dwell), `tool_result_discarded`,
   `protected_speech_window_not_opened` (why), `tool_authorisation_checked` detail (call, causal owner, accepted
   authority, ledger), `reply_claim_rejected` detail (rejected text, binding, workflow, evidence keys).
   Server telemetry ring 500 → 3000.

## Unchanged safety

Wake phrase for protected commands; CriticalSpeechTrustGate; protected window quiet gap and fresh-VAD rule;
single-slot TurnAuthority and mutation consumption; COMMAND_MISMATCH / COMMAND_NOT_CURRENT; two-stage
PREPARE/CONFIRM and TTL; cancellation/expiry; executeVerifiedAction and independent verification; claim gate
(now evaluated against the correct command); server gates; epoch reset.

## Residual risks (measure live)

- Per the documented rule, a speech onset after `reply.done` holds results until that user turn's `reply.done`.
  If VAD fires on TV without the provider producing a turn, the result waits for the next reply.done.
  `tool_result_sent.handoff_dwell_ms` quantifies this.
- The provider still treats locally rejected transcripts as user turns (LLM context drift). Its replies to them
  are now inaudible and own no tools.
- Results of a provider-interrupted reply are dropped (documented behaviour). Authoritative state is unaffected
  and readable; the agent may not mention a mutation that completed.
- Buffering of E1/E2/E3 PCM until the final agent transcript (RC2 claim gate) is retained; it adds latency.
