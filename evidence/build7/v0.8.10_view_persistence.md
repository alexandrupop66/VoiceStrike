# VoiceStrike BUILD 7 v0.8.10 — persistent Worker/Supervisor voice session

## Runtime defect
Switching from Worker to Supervisor unmounted `WorkerView`. Because `VoicePanel` owns `VoiceAgentClient`, its normal React cleanup disconnected the AssemblyAI session. Returning to Worker created a fresh VoicePanel and displayed `Start VoiceStrike`, losing transcript/session continuity.

## Root cause
`App.tsx` conditionally mounted one view at a time (`state && view === ...`). This was a UI lifecycle issue, not a reliability-gate failure.

## Fix
Once dashboard state is loaded, both `WorkerView` and `SupervisorView` remain mounted. The inactive view is hidden with the native `hidden` attribute. The single `VoicePanel` instance remains owned by the persistently mounted WorkerView.

No changes were made to TurnAuthority, CommandRegistry, SafeActionExecutor, speech gates, recovery authority or server mutations. Real disconnect/reconnect semantics remain unchanged.

## Acceptance
Automated: structural assertions prove both views remain mounted and WorkerView contains exactly one VoicePanel.
Runtime R18: active session → Worker → Supervisor → Worker must preserve the same sessionId/transcript with no navigation-induced `connection_lost`.
