# VoiceStrike v0.9.3 — Protected Reply Lifecycle Root Cause and Fix

## Runtime evidence

v0.9.2 accepted `REVERSE_PREPARE` correctly and created PREPARED state. Live telemetry then showed:

1. accepted `REVERSE_PREPARE` on the correct command/action/component;
2. first authorised reply boundary completed;
3. another provider reply began and was suppressed as `NO_ACCEPTED_TURN`;
4. only after that did `reverse_last_scan` arrive;
5. the tool call produced PREPARED and armed `REVERSE_CONFIRM` as `AWAITING_PROMPT_DONE`;
6. because the confirmation-prompt reply lacked reply authority, the protected window never opened;
7. the prepared action later expired without a usable confirmation opportunity.

No mutation endpoint was executed from untrusted confirmation speech. Safety held.

## Root cause

`ReplyAuthorityRegistry` closed an accepted turn at `reply.done` when no pending tool work had yet
been observed. The live provider can deliver the tool.call *after* that boundary. Existing tests
assumed the convenient ordering `markPendingWork -> tool.result -> reply.done`, so they did not
reproduce the live race.

A second lifecycle defect amplified the problem: `CriticalConfirmationGate` started its 20 s TTL at
PREPARED time, before the confirmation prompt was necessarily audible.

## Structural fix

### Protected tool-call lease

Only an already accepted `REVERSE_PREPARE` or `REVERSE_CONFIRM` turn may arm a lease bound to:

- turnId
- commandId
- expected tool = `reverse_last_scan`
- short lease expiry

The lease preserves causal identity across the observed provider boundary. It does **not** grant
tool or mutation authority. While waiting for the exact tool request, extra provider replies remain
unauthorised and inaudible. When the matching tool result is handed back, exactly one
`TOOL_CONTINUATION` reply can deliver the prompt/result.

### Deferred confirmation TTL

PREPARED now stores no worker confirmation deadline initially. The 20 s TTL is activated only when
the authorised confirmation prompt has completed estimated audible playback and the
REVERSE_CONFIRM protected speech window opens. A separate 30 s provider prompt-delivery deadline
prevents indefinite PREPARED state if that prompt never becomes deliverable.

## Safety invariants preserved

- wake phrase remains required for protected commands;
- protected speech still requires exact command/action/component binding;
- fresh VAD / duplex / echo protections remain;
- second confirmation remains a distinct worker turn;
- TurnAuthority remains the operational authority;
- mutation remains single-attempt per accepted authority;
- independent verification remains mandatory before success.
