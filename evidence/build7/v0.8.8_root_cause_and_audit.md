# BUILD 7 v0.8.8 — Root cause proof + full BUILD 7 audit

## 1. Root cause (code inspection of v0.8.7)

Observed runtime telemetry at final confirmation:

```
tool_result = NEEDS_CLARIFICATION
tool_call_attempted = false
"Tool reverse_last_scan blocked because the latest speech was not wake-authorised."
```

That exact string is emitted in only one place in v0.8.7 `client/src/voice/voiceAgent.ts`:

```ts
if (!this.lastInputAuthorised) {           // handleToolCall, first gate
  result = { error: 'AMBIENT_SPEECH_IGNORED', reliability_outcome: 'NEEDS_CLARIFICATION', ... };
  emit('reliability.ambient_ignored', detail: `Tool ${name} blocked because the latest speech was not wake-authorised.`);
}
```

`lastInputAuthorised` is a single mutable field of the session. It is set `true` only when a
`transcript.user` passes all gates, and set `false` in **every** rejected-speech branch of the same
handler:

| v0.8.7 line | branch | sets `lastInputAuthorised = false` |
| --- | --- | --- |
| 544 | `duplexDecision.blocked` (TTS/self-echo, critical during agent audio) | yes |
| 597 | `criticalTrust.critical && !criticalTrust.trusted` (untrusted protected phrase) | yes |
| 642 | `!ambientDecision.accepted` (WAKE_REQUIRED / AMBIENT_IGNORED) | yes |

Sequence that produced the failure:

1. `VoiceStrike, confirm reverse scan B184` is accepted → `lastInputAuthorised = true`, prepared confirmation still pending in `CriticalConfirmationGate`.
2. AssemblyAI begins the reply; the `tool.call` for `reverse_last_scan` is delayed behind LLM/TTS.
3. Any further `transcript.user` in that gap — the agent's own TTS echo (contains "confirm reverse scan B184", so it is critical → `CRITICAL_DURING_AGENT_AUDIO`), a TV/ambient fragment, or a duplicate/late final — is correctly **rejected**, but the rejection also flips `lastInputAuthorised = false`.
4. `tool.call` arrives → first gate reads the flag → blocked. `CriticalConfirmationGate.assessReverse` is never reached, so the prepared confirmation is neither consumed nor executed. Mutation = 0 (safe), success claim = 0 (safe), but a valid confirmation was lost.

The suspected diagnosis in the build prompt is therefore **correct**: accepted authority was stored as mutable latest-session speech state instead of immutable authority bound to the originating turn/command.

Two further defects of the same class were found during the audit:

- `lastFinalTurnId = id` was assigned at the top of `transcript.user`, before any gate. A rejected transcript therefore became the turn id used for `X-VoiceStrike-Turn-Id` and for `assessReverse`. It did not block (server only requires prepared ≠ current turn) but it mis-attributed the audit and weakened the turn binding.
- `X-VoiceStrike-Wake-Authority` was computed from `ambientGate.isActive()` at request time. Rejected speech never extends the 15 s window, so a legitimate delayed tool call after > 15 s of silence would have been refused by the server with `WAKE_AUTHORITY_REQUIRED`.
- `CommandRegistry` cleared `replyCommandId` on correction/supersede/invalidate, so a `tool.call` still arriving from the interrupted reply was re-attributed to the **new** corrected command (`commandForToolCall()` fell through to `active.id`). The entity-argument mismatch gate caught the common case, but authority was transferable in principle.

## 2. Fix (smallest coherent change)

- `client/src/reliability/authority.ts` (new): `TurnAuthority` (frozen) + `TurnAuthorityRegistry` with `grant / resolve / consumeMutation / reset`. No revoke API. Resolution refuses `SESSION_MISMATCH`, `COMMAND_MISMATCH`, `COMMAND_NOT_CURRENT`, `AUTHORITY_EXPIRED` (60 s), `WAKE_NOT_AUTHORISED`, `CRITICAL_SPEECH_NOT_TRUSTED` (reverse only), `MUTATION_ALREADY_CONSUMED`.
- `voiceAgent.ts`: `lastInputAuthorised` removed; `grant()` at acceptance; `resolve()` at `tool.call`; turn id, transcript, wake header and confirmation-gate input derive from the authority; `consumeMutation()` immediately before the mutation request leaves; `reset()` on connect/close/disconnect; `lastFinalTurnId` bound after acceptance only; tool-event UI status `blocked` for non-verified outcomes.
- `commands.ts`: `replyCommandId` no longer cleared on invalidation; `commandForToolCall()` returns the stale id so `isCurrent()`/authority refuse it.
- Agent prompt: two sentences describing `TURN_AUTHORITY_REQUIRED` / `AUTHORITY_ALREADY_CONSUMED`.

Not changed: BUILD 0–6 workflows, server endpoints, two-stage confirmation, trust gates, executor, fault injection, recovery-first reconnect.
